# Release: mxcli v0.30.0

*November 2, 2026*

v0.30.0 is about **catching before the build what would fail at build time or in production, and merging Mendix models from the command line**.

## What's new

**Merge branches outside Studio Pro.** `git merge` can't merge a Mendix model. The `.mpr` is SQLite and every `.mxunit` is BSON, so two branches that both change the model always conflict. `mxcli git merge <ref>` runs Studio Pro's own merge engine (`mx merge`), which also works in a Linux devcontainer:

```bash
mxcli git merge feature/approvals -p app.mpr
```

Whatever the engine resolves is committed as a normal merge commit with Studio Pro's `mx_metadata` note. If the engine needs a decision, nothing lands: the merge is aborted, both sides' changes are printed unit by unit, and a plan file is written next to the project. Pick `ours` or `theirs` per unit in the plan and re-run with `--plan <file>`. Or take one side of every conflict with `--ours` / `--theirs`, or open the merge in Studio Pro for a mixed resolution.

**Security errors before the build, and before production.** Two new lint rules cover access mistakes:

- **SEC012** reports mxbuild's CE2729 ahead of the build: a page a user role can reach that shows an attribute, or lists an entity, the role may not read. On a test project with a role that has no access, it finds the same 27 errors mxbuild does.
- **SEC011** catches a mistake that nothing else does. A page's data source XPath crosses an association the page's roles can't read, so at Production security the page opens to an error dialog, while mxbuild, `check` and `lint` were all clean. It reports the member to grant, and names the widget.

**MPR012** now reports every widget measured as unsupported under the React client (CE0582), with its replacement. A new rule, **CONV021**, merges a create or change followed directly by its commit into one activity. And `check` warns on `trim($Value) != empty`, which is always true, because String functions return `''` and never `empty` (E015).

**Lint a legacy project without the noise.** `mxcli lint --baseline lint-baseline.json --update-baseline` records today's findings. Commit the file, and from then on `mxcli lint --baseline lint-baseline.json` reports only new findings, with an exit code that follows them alone. Custom lint rules can also read more of the model, including access rules, enumeration captions, constant values and project settings.

**Optional page parameters.** `Params: ( $Sale: Shop.Sale optional )` is Studio Pro's unticked *Required* (Mendix 11.5+): the page can be opened without an argument, from a menu item for example.

**Lay out flows your way.** A committed `layout-config.yaml` chooses how `create microflow` and `mxcli layout flows` place what a script leaves unpositioned. Pick the `happy-line` default or `true-right-false-down`, and options such as ELSE as a column under its decision, guard clauses to the right, and a maximum row width.

**`--mcp` uses Studio Pro alone.** The optional Concord server is gone. `--mcp-check` runs Studio Pro's project-wide error check (11.15+), `--mcp-run` starts the app and prints its URL (11.16+), and DROP uses Studio Pro 11.16's native delete. `--mcp http://localhost:<port>/mcp` now also reaches Studio Pro on a Windows machine running Docker Desktop.

**Faster on large projects.** A catalog refresh after a save rebuilds only what the save changed, and no longer re-reads every widget package. `describe` decodes the one document it shows instead of every document of its type.

## Upgrading

Download the `v0.30.0` binary for your platform from the [release page](https://github.com/mendixlabs/mxcli/releases/tag/v0.30.0):

```bash
curl -fsSL -o mxcli \
  https://github.com/mendixlabs/mxcli/releases/download/v0.30.0/mxcli-linux-amd64
chmod +x mxcli && sudo mv mxcli /usr/local/bin/
```

Then refresh a project's skills, commands and the companion mod with `mxcli init --sync-skills`. Every `mxcli init --tool <x>` now installs the bundled lint rules, and `lint` tells you when it runs without them.

Behaviour changes worth knowing:

- The Concord MCP flags `--mcp-concord`, `--mcp-concord-dial` and `--mcp-save` are removed. Studio Pro writes each change to disk as it lands, so there is nothing left to save.
- Integer properties are written as 64-bit integers, as Studio Pro writes them. Documents an older mxcli wrote are not migrated, and reads accept either width.
- The catalog schema moves to version 32, so a cached catalog is rebuilt once. The first command on a project after upgrading also builds the unit index, and now says so.
- `git doctor` no longer reports or writes the `mendix.*` git config keys, which are Studio Pro's own bookkeeping.
