# Release: mxcli v0.31.0

*November 9, 2026*

v0.31.0 is about **publishing your app's microflows as an MCP server, and keeping secrets off the command line**.

## What's new

**Publish microflows as an MCP server.** `create published mcp service` writes the MCP Server 5.x document that Agent Editor starts when the app starts. Each `tool` block exposes one microflow to external agents:

```sql
create published mcp service AgentTest.CustomerMCP (
  EndpointPath: 'customers',
  Version: '1.0.0',
  ProtocolVersion: v2025_03_26
) {
  tool count_customers (
    Microflow: AgentTest.MCPTool_CountCustomers,
    Description: 'Count the customers whose name starts with NamePrefix.',
    Title: 'Count customers'
  )
};
```

The server is served at `<app URL>/customers/mcp`. `alter … add tool / drop tool`, `describe`, `list published mcp services` and `drop` complete the set, and the OAuth settings are there too. `check` reports what the server would refuse at startup: a reserved endpoint path, scopes without an authorization server, or a tool without a microflow. For MCP Server 3.x–4.x, the new `mcp-server` skill builds the same server from startup microflows.

**Agents: tool approval and streaming.** Agent Editor's human-in-the-loop settings now have MDL. A tool can be hidden, shown, or require the user's confirmation (`UserAccessApproval`), with its own display title and description. Backend and UI streaming are switches on the agent. `check` also warns about a model or knowledge base `Provider` that Agent Editor would fail to import at startup.

**Secrets stay off the command line.** The `run` password flags (`--db-password`, `--db-admin-password`, `--screenshot-password`, `--hub-secret`, `--debug-pass`) and `--constant` accept `@env:VAR` and `@file:path`:

```bash
mxcli run --local -p app.mpr \
  --db-password @env:PGPASSWORD \
  --constant MyModule.ApiKey=@file:$HOME/.secrets/api-key
```

`ps` shows the reference, and the run state stores the reference, not the value. A detached run can still be restarted with `run restart`, because each start reads the secret again. A file that its group or others can read is refused, so `chmod 600` it first.

**A brain from day one.** A `brain` can now be started before its project exists (`-C <dir>`), and `mxcli new` adopts it. Entries can be edited and moved without changing their id, can record the document and lines they came from (`--source`), and `brain list --json` returns the committed store as data for tools to read.

**More of the model from MDL.** This release adds:

- `send external object` and `delete external object`, so a flow that holds them survives a describe-and-recreate.
- *Associations to include* on a `call external action` argument.
- A module's version and module type.
- A queued call's retry policy.
- `alter page set` for a Data grid 2 column's attribute and for a text template's parameters.

**`check` catches more before the build.** A case difference in an image reference, a `drop` or `alter` of a document that doesn't exist, and many smaller cases that `exec` or mxbuild would refuse are now reported by `check --references`. `mxcli test --local` starts every run on an empty test database, recovers when `mxbuild --serve` stops answering, and repeats a failed build's errors above the summary line.

## Upgrading

Download the `v0.31.0` binary for your platform from the [release page](https://github.com/mendixlabs/mxcli/releases/tag/v0.31.0):

```bash
curl -fsSL -o mxcli \
  https://github.com/mendixlabs/mxcli/releases/download/v0.31.0/mxcli-linux-amd64
chmod +x mxcli && sudo mv mxcli /usr/local/bin/
```

Then refresh a project's skills and commands with `mxcli init --sync-skills`.

Behaviour changes worth knowing:

- A `--constant` value or a secret `run` flag that starts with `@` is refused unless it is `@env:`, `@file:` or `@@`. Write `@@…` for a value that really starts with `@`.
- Run state (`.mxcli/run-state.json` and friends) no longer stores secrets, and an app folder you copy no longer inherits the original's run state.
- `check --references` matches image names case-sensitively, as Mendix does. A script that relied on the old case-insensitive match now gets an error that names the stored spelling.
- The catalog schema moves to version 34, so a cached catalog is rebuilt once.
